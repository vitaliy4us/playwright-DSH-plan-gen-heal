# Наскрізні тести GreenKart із Playwright Test Agents

[![Playwright tests](https://github.com/vitaliy4us/playwright-DSH-plan-gen-heal/actions/workflows/playwright.yml/badge.svg)](https://github.com/vitaliy4us/playwright-DSH-plan-gen-heal/actions/workflows/playwright.yml)

Набір наскрізних тестів для демонстраційного магазину [GreenKart](https://rahulshettyacademy.com/seleniumPractise/#/), створений за робочим процесом Playwright Test Agents: **планувальник** пише Markdown-план тестування, **генератор** перетворює план на тести Playwright, а **лікувальник** виправляє падіння тестів.

**23 тести — 21 проходить, 2 позначені `test.fixme()`, бо вони документують підтверджені дефекти застосунку** (див. [Звіти про дефекти](Bug%20Reports)).

---

## Що є в репозиторії

| Шлях | Призначення |
|---|---|
| `specs/` | Зрозумілі людині Markdown-плани тестування — джерело істини для того, що покрито |
| `tests/` | Специфікації Playwright, один тест на файл, згруповані за функціональністю |
| `tests/seed.spec.ts`, `tests/fixtures.ts` | Seed-тест і фікстура, яка відкриває застосунок, щоб жоден тест не повторював навігацію |
| `Test Cases/` | Ручні тест-кейси (таблиці крок / очікуваний результат / фактичний результат) |
| `Bug Reports/` | Дефекти, знайдені під час тестування, з ручними кроками відтворення та доказами |
| `.agents/skills/` | Скіли ролей (`playwright-test-planner`, `playwright-test-generator`, `playwright-test-healer`), які дають агенту-програмісту три ролі |
| `.github/agents/` | Визначення агентів Playwright, згенеровані командою `npx playwright init-agents` |
| `SESSION-NOTES.md` | Робоча пам'ять проєкту: рішення, знахідки, особливості середовища |

## Як були створені тести

1. **План** — планувальник досліджує застосунок і пише Markdown-план (`specs/*.md`) з групами, сценаріями, кроками та очікуваними результатами.
2. **Генерація** — генератор виконує кожен сценарій наживо в браузері й пише тест Playwright з того, що справді працювало, один тест на файл.
3. **Лікування** — лікувальник запускає набір тестів, відтворює падіння, знаходить першопричину та застосовує мінімальне виправлення.

Дефекти, знайдені в такий спосіб, не «виправляють» послабленням тесту: тест, що падає й відображає правильні очікування, позначають `test.fixme()` і звітують про нього в [`Bug Reports/`](Bug%20Reports), а тести, які документують поточну (дефектну) поведінку, навмисно залишаються зеленими, щоб зміну в застосунку було помітно.

Визначення агентів у `.github/agents/` згенеровані Playwright і їх слід регенерувати після оновлення:

```bash
npx playwright init-agents --loop=vscode     # or: claude | codex | opencode
```

## Початок роботи

```bash
npm ci
npx playwright install --with-deps chromium
npm test
```

| Скрипт | Що він робить |
|---|---|
| `npm test` | Запускає весь набір тестів |
| `npm run test:headed` | Запуск із видимим браузером |
| `npm run test:ui` | Запуск у режимі Playwright UI |
| `npm run report` | Відкриває останній HTML-звіт |
| `npm run trace` | Відкриває файл трасування в trace viewer |

## Примітки та відомі обмеження

- **Набір тестів працює з живим стороннім сайтом.** Тож червоний запуск CI може означати, що демонстраційний магазин повільний або недоступний, а не регресію. Playwright робить дві повторні спроби й використовує одного воркера в CI (`playwright.config.ts`).
- **Особливості застосунку** задокументовані в планах і в коментарях до тестів, бо їх легко зрозуміти неправильно: знак рупії відмальовується через CSS `::before` і відсутній у тексті елемента; розмітка кошика-панелі присутня в DOM, коли панель закрита; лічильник `Items` у заголовку рахує різні товари, а не загальну кількість; екран підтвердження замовлення залишається видимим понад п'ять секунд; кошик зберігається із затримкою близько однієї секунди.
- **Тести незалежні:** кожен тест отримує свіжий контекст браузера, а `tests/fixtures.ts` відкриває застосунок, тож жоден тест не повторює крок навігації.
