# BUG-2 Заказ можно оформить при пустой корзине — отсутствует валидация

**Серьёзность:** низкая — некорректный сценарий не блокируется (продуктовое решение, требуется подтверждение требований)
**Компонент:** корзина → оформление заказа
**Окружение:** GreenKart `https://rahulshettyacademy.com/seleniumPractise/#/`, Chromium (проект `chromium`), Windows
**Обнаружено:** в цикле plan → generate → heal при исследовании краевых случаев корзины

## Краткое описание

При пустой корзине приложение не блокирует ни один шаг оформления заказа. Пользователь проходит весь путь до «подтверждения» и возвращается на главную страницу так, будто заказ был оформлен.

## Предусловия

Открыта главная страница GreenKart, корзина пуста (`Items : 0`).

## Шаги воспроизведения

| № шага | Описание шага | Ожидаемый результат | Фактический результат |
|---|---|---|---|
| 1 | Нажать иконку корзины | Открывается выпадающая корзина с сообщением «You cart is empty!» | Соответствует ожидаемому |
| 2 | Нажать «PROCEED TO CHECKOUT» | Переход к оформлению заблокирован, либо кнопка недоступна | Переход на `#/cart` выполняется; таблицы товаров нет, итоги нулевые |
| 3 | Нажать «Place Order» | Оформление заблокировано, показано сообщение о пустой корзине | Переход на `#/country` выполняется |
| 4 | Отметить условия и нажать «Proceed» | Оформление заблокировано | Возврат на главную `#/`; экран «Thank you, your order has been placed…» не показывается |

## Доказательства

- На странице `#/cart` при пустой корзине: сообщение «You cart is empty!», таблица `#productCartTables` отсутствует, значения `.totAmt` = 0, `.discountPerc` = 0%, `.discountAmt` = 0 — при этом кнопки «Apply» и «Place Order» **доступны и активны**.
- Переходы подтверждаются URL: `#/cart` → `#/country` → `#/`.
- Для сравнения: при заказе с товарами приложение показывает экран подтверждения «Thank you, your order has been placed successfully…» и лишь затем возвращает на главную. При пустой корзине этот экран не появляется вовсе.

## Влияние

Пользователь может пройти весь процесс оформления, не имея ни одного товара, и получить поведение, неотличимое от успешного заказа. Если у приложения появится серверная часть, это приведёт к созданию пустых заказов. Сейчас (демо-приложение без бэкенда) влияние ограничено ложным ощущением успешного заказа и отсутствием явной обратной связи.

## Рекомендация

Определиться с требованием и привести поведение к нему. Наиболее предсказуемый вариант: на странице корзины при пустой корзине делать «Place Order» недоступной (disabled) либо показывать явное сообщение «Корзина пуста» вместо перехода. Дополнительно — скрывать или блокировать «PROCEED TO CHECKOUT» в выпадающей корзине.
