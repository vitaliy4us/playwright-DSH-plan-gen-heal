# BUG-1 Корзина теряется при перезагрузке страницы сразу после добавления товара

**Серьёзность:** средняя — потеря данных пользователя, временное окно около 1 секунды
**Компонент:** корзина / сохранение состояния (localStorage)
**Окружение:** GreenKart `https://rahulshettyacademy.com/seleniumPractise/#/`, Chromium (проект `chromium`), Windows
**Обнаружено:** в цикле plan → generate → heal; тест `tests/cart-edge-cases/should-persist-cart-after-app-reload.spec.ts`

## Краткое описание

Приложение сохраняет корзину в `localStorage`, но делает это **примерно через секунду после изменения**. Если перезагрузить страницу внутри этого интервала, корзина теряется: при инициализации приложение записывает в хранилище своё текущее (пустое) состояние и затирает ещё не сохранённый товар.

## Предусловия

Открыта главная страница GreenKart, корзина пуста (`Items : 0`).

## Шаги воспроизведения

| № шага | Описание шага | Ожидаемый результат | Фактический результат |
|---|---|---|---|
| 1 | Нажать «ADD TO CART» на карточке «Brocolli - 1 Kg» | Товар добавлен: в шапке `Items : 1`, `Price : 120`, на иконке корзины бейдж «1» | Соответствует ожидаемому |
| 2 | **Сразу же** (в течение ~1 с) нажать F5 / Ctrl+R | Корзина сохраняется: `Items : 1`, `Price : 120` | `Items : 0`, `Price : 0`, бейдж на иконке исчез — корзина пуста |
| 3 | Подождать 1–2 с и перезагрузить страницу ещё раз | — | Корзина по-прежнему пуста: перезагрузка уже перезаписала сохранённое состояние |
| 4 | Повторить шаги 1–2, но подождать ~2 с перед перезагрузкой | Корзина сохраняется | Соответствует ожидаемому — корзина восстанавливается |

Шаг 4 показывает границу дефекта: он воспроизводится только при быстрой перезагрузке, то есть зависит от гонки между записью и перезагрузкой.

## Доказательства

1. **Замер задержки записи.** Программный замер на живой странице: сразу после клика «ADD TO CART» значение в `localStorage` не меняется, запись появляется через **~1009 мс**.
2. **Состояние хранилища после неудачной перезагрузки.** Ключи `app_data_info`, `app_data_qty`, `app_data_tamt` в `localStorage` присутствуют, но их значения — строка `"null"`:

   ```
   localStorage.getItem('app_data_info')  →  "null"
   localStorage.getItem('app_data_qty')   →  "null"
   localStorage.getItem('app_data_tamt')  →  "null"
   ```

   То есть старт приложения записал пустое состояние поверх ещё не сохранённого.
3. **Интерфейс обновляется раньше хранилища.** Перед перезагрузкой счётчики уже показывали `Items : 1` — значит отстаёт именно запись в `localStorage`, а не состояние в памяти.

## Влияние

Пользователь теряет собранную корзину, если обновит страницу (F5) сразу после добавления товара. Теряется не количество, а вся позиция. Воспроизводимость: стабильно высокая при быстрой перезагрузке; на медленном устройстве окно может быть больше, на быстром — меньше. На первый взгляд дефект «незаметен», потому что в обычном сценарии (добавил → походил по каталогу → перезагрузил) корзина восстанавливается корректно.

## Гипотеза о причине

Сохранение в `localStorage` выполняется отложенно (debounce или интервал ~1 с) вместо синхронной записи при изменении состояния корзины. При инициализации приложение записывает актуальное (пустое) состояние, не проверяя, есть ли несохранённые изменения.

## Обходной путь

Подождать 1–2 секунды после изменения корзины перед перезагрузкой страницы.
